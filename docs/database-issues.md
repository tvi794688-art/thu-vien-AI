## Concurrency Assessment

`borrow_book` locks the selected `books` row `FOR UPDATE` before reading availability, validates the value after obtaining the lock, then decrements and inserts the loan in the same function transaction. Under PostgreSQL's normal READ COMMITTED isolation, concurrent RPCs for the same book serialize on that row. The waiting call sees the committed reduced availability and rejects if it is now below one. Therefore concurrent calls through this RPC cannot both consume the same final copy. This assessment is limited to calls routed through this function; direct table writes are not protected by the same business validation, which is covered by DB-004.

`return_book` locks the loan row `FOR UPDATE`; concurrent returns of the same loan serialize, and the second call sees `returned` and raises before changing availability or creating another fine. Status, inventory increment, and fine insertion share the function transaction. The absence of an upper-bound inventory constraint still leaves non-RPC writes or preexisting inconsistent values unguarded (DB-004).
